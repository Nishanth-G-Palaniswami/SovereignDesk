# CLAUDE.md

Instructions for Claude Code sessions working in this repo. Not user documentation.

## What this is

SovereignDesk: an always-on import-compliance triage agent for U.S. customs brokers.
Shipment JSON lands in a watched folder. A deterministic Node engine classifies HTS,
flags PGA requirements, computes the duty stack, and lists missing LPCO documents. A
local LLM writes a plain-English memo. A broker approves or reclassifies from their
phone. Every reclassification is stored as institutional precedent.

Architectural story: build a hedge fund that doesn't forget. The LLM is transient and
swappable. The memory layer is permanent and lives on the box. Customs is the first
vertical, not the product.

Entry for the Dell x NVIDIA "Local AI on Dell Pro Max with GB10" hackathon, NYC,
Saturday 2026-08-22, submission via BuilderBase. The team is continuing past the event
window, so this is no longer a same-day sprint, but the discipline stands: bias to the
smallest change that works, do not refactor, do not restructure, do not "improve on the way
past". If something looks wrong but is not on the critical path, say so and leave it.

**`PLAN.md` is the single plan** and it wins over anything else. `docs/DATA_SWAP.md` is
the data-provenance appendix. Agent standing orders live in `agent/AGENTS.md`.
`docs/superseded/` holds older plans that contradict the current one on the review channel,
the tariff data and the demo numbers. Never brief from them.

## Hard architectural invariant: the engine decides, the LLM only explains

**The model never picks an HTS code, a rate, a PGA flag, or a duty figure.**

The deterministic engine proposes candidates with scores, a confidence, and a full
`trace[]`. The LLM reads `results/<id>.result.json` and turns it into prose. Every number
and flag in a memo must be traceable to a field in the engine output.

This is the answer to every hallucination question a judge asks. Do not weaken it:

- Never add a code path where model output is written into `hts`, `mfn_rate`,
  `total_rate`, `duty_est`, or `flags`.
- Never let the agent hand-edit a result file. The only write path for an override is
  `record_precedent.mjs`.
- If a prompt change would let the model "fix" a classification, reject it and fix the
  data or the scoring instead.

Classification is keyword scoring over `engine/data/hts_subset.csv`.
`confidence = topScore / (topScore + secondScore)`. `CONFIDENCE_FLOOR` is `0.70`
(`engine/triage.mjs:27`); below that the line gets `LOW_CONFIDENCE` and routes to a human.
`PRECEDENT_FLOOR` is `0.55` (`engine/triage.mjs:176`).

`shipment_summary.status` is `READY` or `NEEDS_REVIEW`. Flags include `LOW_CONFIDENCE`,
`LPCO_MISSING`, `PGA_CONFIRM`, `DECLARED_DIFFERS`, `PRECEDENT_APPLIED`,
`PRECEDENT_UNKNOWN_CODE`, `DECLARED_NOT_IN_TABLE`, `NO_CANDIDATE`.

## Commands

Sweep the inbox. This is the one command the agent runs per cron tick:

```bash
node engine/process_inbox.mjs --root <workspace>
```

Reads `<workspace>/inbox/*.json`, writes `<workspace>/results/<id>.result.json`, moves the
input to `processed/`, quarantines unparseable files to `inbox/_failed/`. Prints
`{ precedent_store, shipments: [...] }` on stdout.

Classify a single shipment:

```bash
node engine/triage.mjs <shipment.json> [--data <dir>] [--precedents <file>] [--out <file>] [--pretty]
```

Record a broker override as a precedent:

```bash
node engine/record_precedent.mjs --shipment <id> --line <n> --hts <code> --reason "..." --root <workspace>
```

Rebuild the tariff tables from the USITC export:

```bash
node scripts/build_hts_from_usitc.mjs --archive engine/data/usitc/hts_2026_rev_7.json
```

Smoke test: `scripts/smoke.sh`.

## Data rules

`engine/data/usitc/hts_2026_rev_7.json` is a public U.S. government export from
hts.usitc.gov (2026 revision 7, 35,496 rows, 19,856 ten-digit lines). **It is the source of
truth for every rate in this repo.**

- **Never hand-edit a rate in `engine/data/hts_subset.csv`, `hts_full.csv`, or
  `surcharges.json`.** Rebuild them with `scripts/build_hts_from_usitc.mjs`. Hand-typed
  rates are exactly what the data swap removed.
- Keywords in `hts_subset.csv` are curated and are **not** regenerated by the build
  script. Editing a keyword is a legitimate classification fix; editing a rate is not.
- **Indent-inheritance gotcha:** rates and footnotes live on the nearest *ancestor* with a
  value. Read a 10-digit line on its own and `general` is almost always blank. You must
  walk the `indent` hierarchy. The build script does this. Anything that reads the USITC
  JSON directly must do it too, or it will silently produce zeros.
- The MFN rate is the line's `general` field. Section 301 membership is a footnote pointing
  at a Chapter 99 heading, and that heading states its own surcharge in plain text, so the
  surcharge is **read, not assumed**. `surcharges.json` carries `authority_by_prefix`
  across 1,184 prefixes so every surcharge cites the heading that set it.
- **Section 122 is disabled and stays disabled.** It was adding a fabricated flat 10% to
  every line. No 9903 subchapter implementing it exists in the 2026 schedule. Re-enabling
  it requires a citation to a live Chapter 99 heading, not a config edit.
- **Entry-level fees are computed on the ENTRY, not per line** (`engine/triage.mjs:265`).
  MPF is clamped to a per-entry minimum and maximum, and folding it into a per-line
  ad-valorem rate silently breaks that clamp on any multi-line entry. HMF is vessel only and
  keys off the shipment's `mode`. The MPF min and max are reset every fiscal year by CBP and
  the committed figures are marked `VERIFY-CBP-FY2026`, so do not quote them as fact.
  `effective_rate` stays duty-only on purpose; fees are reported separately.
- `pga_flags.json` and `lpco_rules.json` are still demo tables and lane 3 owns them. Together
  with the `VERIFY-CBP-FY2026` MPF clamp above they are the two placeholder surfaces left in
  the repo. Say so out loud rather than implying they are authoritative.

### precedents.jsonl

Append-only JSON Lines at the **workspace root, on the host mount**. One line per broker
override: `sig`, `description`, `hts`, `reason`, `by`, `shipment_id`, `line`, `at`.

- **Never edit it. Never delete a line. Never rewrite it.** A wrong precedent is superseded
  by a new `reclassify`, not erased. It is the audit trail.
- Only `record_precedent.mjs` appends to it.
- Retrieval is Jaccard similarity over sorted description tokens, so it generalises across
  rewording instead of needing an exact string match.
- NemoClaw is **not** the memory layer. NemoClaw is the install and stack layer. Anyone who
  says "NemoClaw stores the precedents" is wrong.

## Gotchas

- **The box is ARM64 (aarch64)**, DGX OS / Ubuntu 24.04, 128 GB unified memory. **x86
  container images will not run.** Do not hand-roll Docker: it fights the required stack
  (OpenClaw, NemoClaw, OpenShell) and avoiding container pulls on venue wifi is the whole
  point of the Ollama path.
- **The sandbox cannot reach `localhost` directly.** All inference goes through OpenShell's
  `inference.local` proxy. NemoClaw wires this up; do not hand-roll it.
- **The precedent store must stay on the host mount, never inside the sandbox.** The
  teardown demo (destroy the sandbox with `nemoclaw <sandbox> rebuild`, the broker's
  override still applies) is the strongest beat available and it breaks the moment
  `precedents.jsonl` lives inside the sandbox filesystem. `process_inbox.mjs:33` puts it at
  `<root>/precedents.jsonl` for exactly this reason.
- **Human review is a LOCAL CONSOLE, not a chat channel.** `lanes/6-channel-ui/server.mjs`
  on `127.0.0.1:7777`, zero dependencies, loopback only. The network policy is drop with
  **no allowlist at all**: not "only a text memo leaves" but "nothing leaves". Telegram and
  Matrix are both superseded. A Matrix spike survives at `lanes/6-channel-ui/matrix_bridge.mjs`
  for possible later remote approval over a private mesh; it is not built into the demo.
- **One writer per artefact.** The agent writes memos. The console handles human actions and
  shells out to `record_precedent.mjs` for a reclassify. Do not add a second write path into
  `decisions/` or `precedents.jsonl`.
- The tokenizer and `signature()` are duplicated in `engine/triage.mjs` and
  `engine/record_precedent.mjs`. **Edit one, edit both**, or precedents stop matching.
- Do not change engine field names mid-event. The result shape is frozen
  (`engine/triage.mjs:13`); the agent prompt and the projector board both read it.

## Resolved: sample 001 reaches READY

**RESOLVED 2026-08-22.** Line 1 is "Cast iron pump casing for centrifugal liquid pump,
without engine". A casing is a part of a pump, not a pump, and the engine used to rank the
complete pump first at confidence 0.54.

The cause was a side effect of the USITC data swap. `rowIsParts` tested
`rowDesc.has("part")`, and after the swap every description is the joined ancestor heading
text, which for chapter 8413 reads "Pumps for liquids ... part thereof:". That made it true
for the whole-machine row as well, so the `+4` parts boost cancelled and the halving at
`:145` never ran at all.

Neither obvious one-liner worked, and both were measured on all six samples: moving the
penalty from 0.5 to 0.35 alone moved zero samples, and trimming the greedy `liquid pump`
keyword flipped the code but left confidence at 0.54.

The fix is both halves together: `:143` now tests the heading path for a real segment,
`/(?:^|,)\s*parts:/i`, and `:145` is 0.35. Sample 001 line 1 is now `8413.91.90.96` at
**0.77**, READY. Sample 004 line 1 goes 0.73 to 0.92. Samples 002, 003, 005 and 006 are
unchanged cold and warm, so the precedent demo is untouched. Duty on 001 does not move
($1,015 on $4,000): both 8413 lines are Free MFN plus 25% Section 301, so this was about
being right, not about money. `scripts/smoke.sh` now asserts all three values.
